# agent-purge — как пользоваться

Одна персона — много coding-агентов. Инструмент подменяет (или дописывает) системный промпт
у codex, claude, opencode, grok, omp, hermes, pi, zcode, antigravity, codebuddy и других,
и всё это обратимо одной командой.

> Это русская инструкция к форку. Оригинал: <https://github.com/ZiChuanLan/agent-purge>.
> Требуется Node ≥ 20, зависимостей нет.

---

## 1. Как он работает (одна минута)

У каждого агента свой способ задать системный промпт. agent-purge сводит их к трём каналам:

| Канал | Что делает | Когда действует |
|---|---|---|
| `install` | пишет в «родной» конфиг агента (managed-блок в Markdown, плагин, `model_instructions_file`) | постоянно, даже если агент запустили не через agent-purge |
| `shim` | кладёт в начало `PATH` маленькую обёртку с тем же именем и передаёт запуск в `agent-purge <агент>` | когда набираешь команду руками |
| `slash` | команда в сессии — `/purge on\|off\|status` | во время работы, без перезапуска |

Все три канала читают один и тот же текст — файл персоны. `off` или снятый флаг возвращают
всё как было.

## 2. Установка

```bash
npm i -g agent-purge          # или из этого репозитория:
git clone https://github.com/shnaps666/agent-purge
cd agent-purge && npm i -g .
```

Проверка:

```bash
agent-purge doctor            # что установлено на машине и какие версии
agent-purge matrix            # таблица возможностей по каждому агенту
```

---

## 3. Быстрый старт

```bash
agent-purge ls                # список персон, * — текущая
agent-purge use neutral       # выбрать персону
agent-purge mode replace      # режим подмены
agent-purge opencode          # запустить opencode уже с этой персоной
```

Дальше — по вкусу: `agent-purge codex`, `agent-purge claude`, `agent-purge pi --ask "что тут делается?"`.

---

## 4. Персоны

Персона — это Markdown-файл в `~/.agent-purge/personas/<id>.md`:

```markdown
---
description: краткое описание для списка и веб-консоли
order: 10
---

Тут текст, который попадёт в системный промпт.
Пишите как обычно: правила, стиль, запреты, язык ответов.
```

- `description` — подпись в `ls` и в веб-интерфейсе (`desc` тоже принимается).
- `order` — порядок сортировки (необязательно).
- `harness` / `model` — привязка персоны к конкретному агенту или модели (необязательно).

Файл `active.md` в той же папке — **производный**: его пересобирает сам инструмент, руками не правьте.

Часто используемые команды:

```bash
agent-purge use <id>                    # сделать персоной по умолчанию
agent-purge pi --persona <id>           # только для этого запуска
agent-purge ls                          # показать все, отметить текущую
```

## 5. Режимы

```bash
agent-purge mode replace   # (по умолчанию) заменить системный промпт целиком
agent-purge mode strict    # оставить ТОЛЬКО персону (описания инструментов тоже уйдут)
agent-purge mode append    # дописать персону к родному промпту
agent-purge mode off       # ничего не менять
```

`strict` честно вырезает всё, включая инструкции по инструментам — агент может «поглупеть»,
зато посторонних правил в промпте не останется.

## 6. Постоянная установка (каналы)

```bash
agent-purge arm opencode            # включить все каналы разом (常驻 + shim + slash)
agent-purge arm opencode --install   # только конфиг/плагин
agent-purge arm opencode --shim      # только перехват имени команды
agent-purge arm opencode --slash     # только команду в сессии (реально работает у pi)

agent-purge arm --all                # то же для всех установленных агентов
agent-purge disarm opencode          # снять всё у одного
agent-purge disarm --all             # снять везде
agent-purge status                   # таблица: где что включено
```

Важно про переключение персоны:

- **opencode** — плагин читает `state.json` и текст персоны **на каждый запрос**, поэтому
  `use`/`mode` применяются со следующего сообщения, перезапуск не нужен;
- **pi** — то же через расширение и `/purge`;
- **codex / claude / grok / omp / hermes / zcode** — в их конфиг пишется **снимок** текста,
  так что после смены персоны нужно повторить `agent-purge arm <агент> --install`;
- **claude** — файл `~/.claude/CLAUDE.md` попадает в контекст как `<system-reminder>`, то есть
  в пользовательский слой, а не в системный; полноценно подменить промпт можно только запуском
  через `agent-purge claude`. Инструмент об этом честно пишет в `status`.

## 7. Веб-консоль

```bash
agent-purge web                  # → http://127.0.0.1:7788
agent-purge web --port 7789      # другой порт
agent-purge web --detach         # запустить в фоне и вернуть терминал
```

В браузере выбираете агента, персону и режим, включаете/выключаете каналы кнопками.
Изменения пишутся сразу в `state.json`.

Про безопасность: консоль слушает только `127.0.0.1` и принимает изменения **только** с
одноразовым токеном, который сам подставляет в страницу. Любой сторонний сайт получит `403` —
это защита от того, чтобы открытая вкладка не могла переписать системный промпт вашим агентам.

Если дёргаете API руками (curl), токен нужно взять из исходника страницы:

```bash
curl -s http://127.0.0.1:7788/ | grep -o 'window.__AP_TOKEN__ = "[^"]*"'
curl -X POST http://127.0.0.1:7788/api/use \
  -H 'Content-Type: application/json' \
  -H "x-agent-purge-token: <токен из строки выше>" \
  -d '{"id":"neutral"}'
```

## 8. Откат — всё обратимо

```bash
agent-purge mode off             # перестать менять промпты (самый быстрый способ)
agent-purge disarm --all         # снять shim/плагины/команды у всех
agent-purge uninstall <агент>    # удалить только постоянную установку у одного
agent-purge status               # убедиться, что нигде не осталось
```

`shim` удаляется из начала `PATH`, managed-блоки вырезаются по маркерам, файлы плагинов
удаляются. Если что-то осталось — `status` покажет, где именно.

## 9. Где лежат данные

```
~/.agent-purge/
├── state.json          # персона по умолчанию, режим, какие каналы включены
├── personas/<id>.md    # ваши персоны
└── personas/active.md  # производный файл (не править)
```

Другое место:

```bash
# Linux/macOS
export AGENT_PURGE_HOME=/path/to/data
# Windows
setx AGENT_PURGE_HOME D:\ap-data
```

Данные лежат отдельно от кода, поэтому обновление пакета персоны не стирает.
Для бэкапа достаточно скопировать эту папку.

## 11. Частые проблемы

**opencode: плагин отмечен как `failed`.** В opencode 2.x плагины обязаны быть в форме V2 —
`export default { id, setup(ctx) }`. Старые V1-плагины (функция, возвращающая
`"experimental.chat.system.transform"`) загрузчик отклоняет. Кроме того, список плагинов
кэшируется на время жизни сервера — после правки файла перезапустите его:

```bash
opencode service restart
opencode plugin list
```

**Персона сменилась, а агент отвечает по-старому.** У codex/claude/grok/omp/hermes конфиг —
это снимок: повторите `agent-purge arm <агент> --install` (или `mode off`, если нужен откат).

**Веб-консоль не принимает изменения.** Значит запрос идёт без токена — либо из curl без
заголовка `x-agent-purge-token`, либо с чужого origin. Откройте страницу заново, токен
перевыпускается при старте процесса.

**Порт занят.** Запустите на другом порту (`agent-purge web --port 7789`) либо закройте старый
экземпляр: на Windows — `Get-NetTCPConnection -LocalPort 7788 -State Listen`, затем
`Stop-Process -Id <PID>`; на Linux/macOS — `lsof -i :7788` и `kill <PID>`.

## 12. Границы: что он не делает и где оговорки

- **Лицензии.** Не обходит, не «разблокирует», не подменяет проверки подписки. Единственный
  побочный эффект — изменённый текст системного промпта.
- **Сеть.** В рантайме запросов нет: `lib/`, `bin/`, `web/` работают только с локальными
  файлами, состояние лежит в `state.json`. Единственный `fetch` в репозитории — в отладочном
  `bench/judge-armor.mjs`, который в обычной работе не участвует.
- **Бинарники — есть два исключения, и о них надо знать.** По умолчанию CLI правит только
  текстовые конфиги и плагины, но в `matrix.json` у двух агентов стоит `patch: true`:

  | Агент | Что заявлено | Статус |
  |---|---|---|
  | `claude` | запуск `--system-prompt-file` + «остаточное 62-символьное предложение с именем срезается `patch-claude.mjs`» | **скрипта `patch-claude.mjs` в репозитории нет** — это рецепт, а не автоматика |
  | `antigravity` | `binary-patch`: равнозначная замена строки в `resources/bin/language_server.exe` | `inject: false` — то есть подмена не подтверждена, только рецепт |

  Практический вывод: ничего не патчится «само», но и утверждать «бинарники вообще не трогаем»
  было бы неправдой — для этих двух агентов проект описывает ручную правку бинарника.
- **`qoder` и `workbuddy` — `unsupported`.** Их системный промпт собирается на сервере,
  поэтому ни `shim`, ни `install` его не перехватывают (так и написано в причинах отказов
  `lib/caps.mjs`). Правке доступны только файлы контекстных правил, и это влияет слабее.
- **`zcode`** — только документально: десктопная версия закрыта, проверить, читает ли она
  `~/.zcode/AGENTS.md`, невозможно; проект честно помечает это как непроверенное.
